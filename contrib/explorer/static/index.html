UNNUMBERED BIP DRAFT

Three operations. Existing Bitcoin restrictions.

Test OP_TEMPLATEHASH, OP_CHECKSIGFROMSTACK, and OP_INTERNALKEY from BIP 448. This signet implements the unnumbered BIP draft for their use under RDTS, based on Bitcoin Knots. No BIP number has been assigned; production activation is unspecified.

How this differs from upstream BIP 448

The opcode numbers, SHA256 template hashes, and BIP 340 signatures are unchanged. RDTS retains 256-byte stack elements, a maximum of seven Taproot Merkle branch hashes, no annexes, and no Tapscript OP_IF or OP_NOTIF.

RDTS already rejects unknown OP_SUCCESS operations at consensus. Allowing these operations therefore requires a coordinated consensus upgrade, unlike upstream BIP 448’s soft-fork approach. Existing participants need paperclip-signet3-template-csfs or later. See the upgrade instructions.

From height 3250, CSFS must consume exactly the current input’s 32-byte TEMPLATEHASH. This is a fixed consensus rule, with no configurable size opt-out. Updated nodes reject arbitrary CSFS messages from the mempool immediately. Historical blocks retain their earlier rules. This narrows BIP 348/BIP 448 and does not eliminate other data-carrying paths.

Blocks target one minute; test coinbase outputs mature after 100 blocks.
